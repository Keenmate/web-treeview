DS01 · Path-Based Data Structure

The tree builds its hierarchy from materialized path strings. Each item carries a unique path that encodes its position: '1' is a root, '1.1' a child of '1', '1.1.2' a grandchild. The pathMember tells the tree which property holds the path.

// Each item's path encodes its position
const data = [
  { id: 1, path: '1',     name: 'Root' },
  { id: 2, path: '1.1',   name: 'Child 1' },
  { id: 3, path: '1.2',   name: 'Child 2' },
  { id: 4, path: '1.1.1', name: 'Grandchild' }
];

tree.nodes = data;
tree.idMember = 'id';
tree.pathMember = 'path';
tree.displayValueMember = 'name';

How paths work

  • Path "1" — a root node
  • Path "1.1" — a child of "1"
  • Path "1.1.1" — a child of "1.1" (grandchild of "1")
  • The separator (default .) splits a path into segments; the number of segments is the node's level.

DS02 · Display Value Fallback

A node's label resolves in order: displayValueMember → displayValueCallback → labels.noDisplayValue. When a tree configures neither a member nor a callback (or a node has no data for that member), the labels.noDisplayValue text is shown instead. Default is "[N/A]"; set it to "" to render nothing.

Type here — the right-hand tree updates live.

With display-value-member="name"

No member → fallback

// No displayValueMember and no callback → every label uses the fallback
tree.idMember = 'id';
tree.pathMember = 'path';
tree.labels = { noDisplayValue: '(no name)' };

DS03 · Custom Path Separators

Set tree-path-separator (property treePathSeparator) to change the delimiter between path segments. Handy when your identifiers already contain dots, or when mirroring real file paths / namespaces.

Slash separator "/" (file paths)

tree.treePathSeparator = '/';
tree.nodes = [
  { id: 1, path: 'home',               name: '/home' },
  { id: 2, path: 'home/user',          name: '/home/user' },
  { id: 3, path: 'home/user/docs',     name: '/home/user/docs' }
];

Double-colon separator "::" (namespaces)

tree.treePathSeparator = '::';
tree.nodes = [
  { id: 1, path: 'App',                name: 'App' },
  { id: 2, path: 'App::Services',      name: 'App::Services' },
  { id: 3, path: 'App::Services::Auth', name: 'App::Services::Auth' }
];

DS04 · Branch Operations

addBranch(parentPath, data[]), replaceBranch(parentPath, data[]), and removeBranch(path, keepParent?) bulk-mutate a whole subtree in one call, each emitting a single change. Ideal for server-driven moves: snapshot a branch, send it off for path/ID recalculation, then delete the old branch and insert the recalculated one.

Operation log:

Run a branch operation
// addBranch(parentPath, data)  → { success, count, failed: [{ data, error }], parentNode }
//   every item is placed by its own path (whole subtrees OK); an item with a
//   missing/empty path, a duplicate path, or a path not under parentPath is in `failed`
// replaceBranch(parentPath, data) → the same + { removed, added }
// removeBranch(path, keepParent?) → { success, count }

const res = tree.addBranch('1.1', [
  { id: 101, path: '1.1.9',   name: 'New Team' },
  { id: 102, path: '1.1.9.1', name: 'Member A' }
]);
// removeBranch('3')          → remove "Sales" and all descendants
// removeBranch('1.2', true)  → clear children, keep the "Design" node
