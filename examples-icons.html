IC01 · FontAwesome classes + per-node color

icon-member resolves a class string; it renders as <i class="wtv__node-icon {value}"> on every node. The chevron stays on branches — the icon is its own element beside it. icon-color-member colors each icon.

Because web-treeview uses Shadow DOM, page CSS doesn't reach the fa-* classes: FontAwesome goes in through custom CSS, which has two layers. The page layer window.components['web-treeview'].customStyles (or .getCustomStylesCallback(ctx)) styles every tree on this page — it holds the FontAwesome @import, which core also links once in the document head so the icon font registers. The instance layer comes after it and overrides it: this tree's custom-styles attribute (customStyles property) enlarges its icons; getCustomStylesCallback wins over it when both are set. 

// page layer: every <web-treeview> on the page
window.components['web-treeview'].customStyles =
    '@import url("https://cdnjs.cloudflare.com/ajax/libs/font-awesome/6.5.1/css/all.min.css");';

<!-- instance layer: this tree only, after the page layer -->
<web-treeview icon-member="icon" custom-styles=".wtv__node-icon { font-size: 1.1em; }">

IC02 · Emoji via getIconCallback

An emoji needs no font — the value's text renders directly. Use a callback to derive it.

IC03 · Inline SVG via renderIconCallback

For full control, renderIconCallback({ node, value, iconElement }) populates the icon element — here a Lucide-style SVG. Color flows from icon-color-member onto the element, so stroke="currentColor" tints the SVG.

IC04 · Lucide SVGs (data-keyed) via renderIconCallback

A data member holds a Lucide icon key (map-pin, shield, user-star, coffee, user) exposed via icon-member; renderIconCallback receives that resolved value (ctx.value) and paints the matching inline SVG with stroke="currentColor", so icon-color-member tints each glyph. Icons from the pure-admin Lucide set.
