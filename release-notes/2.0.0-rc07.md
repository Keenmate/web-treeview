# Web TreeView 2.0.0-rc07 — Release Notes

**Released:** 2026-11-22 · **Pre-release** (`npm install @keenmate/web-treeview@rc`)

These notes cover the changes since **2.0.0-rc06**, the last version on npm. They are the first
release notes for this package; for earlier versions read the
[CHANGELOG](https://github.com/Keenmate/web-treeview/blob/prod/CHANGELOG.md).

This rc moves the rest of the tree's plumbing onto `@keenmate/web-components-core` rc25 and the
shared Keenmate rules: render callbacks return their content (core `renderSlot`), node icons go
through core `renderIcon`, UI strings through core `/locale` (flat keys, a page-wide dictionary,
`translateCallback`, `locale`), selection through core `createSelection`, touch drag through core
`createPointerDrag`. The tree gains ARIA tree semantics, screen-reader announcements, right-to-left
support, `disabled` / `readonly`, an animated expand / collapse and a public engine / headless state
for building your own UI (`TreeViewEngine`, `TreeViewState`). It is **breaking, with no aliases.**
Note that a `^2.0.0-rc06` range **does** pull this rc (npm matches later prereleases of the same
`2.0.0`), so pin the version until the checklist below is done.

The exhaustive, per-change list is in
[`CHANGELOG.md`](https://github.com/Keenmate/web-treeview/blob/prod/CHANGELOG.md) (section
2.0.0-rc07); this document is the upgrade guide and the highlights.

## Breaking changes

### `el.update(props)` is removed — use `el.setAttributes()`

The element's `update()` is core's protected hook now (no alias). Write several inputs at once with
core's `el.setAttributes(props)` (config keys or attribute names): one validated batch, one engine
update, and it returns the refused values (each also fires `input-rejected`). The rc06 public
`update()` bypassed the input pipeline — no validation, and the element's config never saw the
values, so the next unrelated write (or a responsive re-run) sent the previous `nodes` again and the
tree reloaded them. The `TreeViewMethods` type no longer lists `update`.

```js
// rc06
tree.update({ nodes, expandLevel: 2 });
// rc07
tree.setAttributes({ nodes, expandLevel: 2 });
```

### The `theme` attribute is removed

`theme` / `TreeViewConfig.theme` copied its value onto the inner `.wtv__container` — a second switch
next to `data-theme`, which every Keenmate component reads. Force one tree's scheme with
`data-theme="dark"` / `"light"` on `<web-treeview>`; a standalone engine puts `data-theme` on its own
container. The order is per-instance `data-theme` → the page / `theme-source` signal → the inherited
`color-scheme`.

### Render callbacks return their content

`renderNodeCallback`, `renderHeaderCallback`, `renderFooterCallback`, `renderEmptyStateCallback` and
`renderEmptyZoneCallback` return their content (core `renderSlot`) instead of filling an element;
`ctx.contentElement` / `ctx.containerElement` are gone.

| Return | Result |
|---|---|
| a string | HTML |
| a `Node` | mounted |
| `null` / `undefined` | the built-in content (the node label, `messages.noData` / `messages.noResults`, the `messages.dropHere` box; header / footer: empty) |
| `false` | the slot is emptied and `hidden` |

```js
// rc06
tree.renderNodeCallback = ({ node, contentElement }) => { contentElement.innerHTML = `<b>${esc(node.data.name)}</b>`; };
// rc07
tree.renderNodeCallback = ({ node }) => `<b>${esc(node.data.name)}</b>`;
```

In rc06 a callback that filled nothing left the slot empty; it now draws the built-in content.
Removing `renderNodeCallback` brings the built-in labels back (rc06 rows kept the custom content).
`renderLoadingCallback` keeps its shape. When a node callback re-runs is described under
[Render callbacks re-run only when their input changes](#render-callbacks-re-run-only-when-their-input-changes).

### `renderIconCallback` takes the core shape

Node icons are drawn by core `renderIcon` — the order every Keenmate component uses: markup
(`<svg …>`) as is → a core built-in name (masked `--base-icon-*` glyph) → this tree's
`renderIconCallback(name, ctx)` → the page-wide `window.components.renderIconCallback(name, ctx)` →
a class list as an icon-font `<i>` → text.

| rc06 | rc07 |
|---|---|
| `renderIconCallback(ctx) => void`, filling `ctx.iconElement` (`ctx.value`) | `renderIconCallback(name, ctx) => markup \| null` — asked only for a node with an icon value that isn't markup or a built-in name; `null` / `undefined` = not mine |
| `<i class="wtv__node-icon fa-solid fa-user">` | `<span class="wtv__node-icon"><i class="wtv__icon fa-solid fa-user" aria-hidden="true"></i></span>` |
| `user`, `check`, `close`, `settings`, `delete`, … → icon-font class | → core's built-in glyph; another one-word value (`gear`) is still a class |
| `renderIconCallback` alone gave every node a wrapper | a node without an icon value has no wrapper (unless `align-node-icons` reserves the column) |

```js
// rc06
tree.renderIconCallback = ({ node, iconElement }) => { iconElement.innerHTML = node.hasChildren ? FOLDER_SVG : FILE_SVG; };
// rc07 — per-node markup from the value …
tree.getIconCallback = ({ node }) => (node.hasChildren ? FOLDER_SVG : FILE_SVG);
// … or your own icon names mapped by the hook
tree.iconMember = 'icon'; // data: { icon: 'lucide-folder' }
tree.renderIconCallback = (name) => (name.startsWith('lucide-') ? lucideSvg(name.slice(7)) : null);
```

The wrapper's colour, the `--wtv-node-icon-*` tokens and `--aligned` are unchanged.

### UI string keys are flat `<elementType>.<name>`

Every `labels` key follows the core `/locale` shape. English defaults are unchanged. rc06's
`loading` fed the `isLoading` overlay's `aria-label`; it is `ariaLabels.loading` now, and the
loading row of a lazy context submenu has its own `messages.loading`.

| rc06 key | rc07 key |
|---|---|
| `noData` / `noResults` / `dropHere` | `messages.noData` / `messages.noResults` / `messages.dropHere` |
| `loading` | `ariaLabels.loading` (+ new `messages.loading` for the lazy submenu row) |
| `noDisplayValue` | `labels.noDisplayValue` |
| `showFullLabel` | `ariaLabels.showFullLabel` |
| `copy` `cut` `paste` `delete` `expand` `collapse` `expandSubtree` `collapseSubtree` `expandAll` `collapseAll` `sort` `sortSubtree` `sortAll` | `menuItems.<same>` |

The instance `labels` take the short key (`messages.noData`) or the full key
(`web-treeview.messages.noData`). The keys that are new in this release are listed under
[New features — localization](#new-features--localization).

### Dynamic labels read their context (`{ctx.*}`)

A label with values gets its spot's context as `{ ctx }` (core `/locale` dotted paths, numbers formatted
in the tree's `locale`): templates read `{ctx.count}`, `{ctx.name}`, `{ctx.target}`, `{ctx.searchTerm}` —
bare `{count}` / `{name}` / `{target}` are no longer filled (no aliases). A `translateCallback` gets the same
object as `params.ctx`; `ctx.count` is the number the text's noun agrees with, so the app's i18n picks the
plural form (core never does). The contexts are exported types.

| Key | Context | Earlier template | Now |
|---|---|---|---|
| `ariaLabels.searchResults` | `SearchResultsLabelContext` `{ count, searchTerm }` | `{count} results` | `Results: {ctx.count}` |
| `ariaLabels.searchResultsOne` | — | `1 result` | **removed** (`searchResults` with `ctx.count` = 1) |
| `ariaLabels.searchNoResults` | `SearchResultsLabelContext` (`count` = 0) | `No results found` | unchanged |
| `ariaLabels.movedInto` / `movedBefore` / `movedAfter`, `copiedInto` / `copiedBefore` / `copiedAfter` | `DropLabelContext` `{ name, target, count }` | `{name} moved into {target}` … | `{ctx.name} moved into {ctx.target}` … |
| `ariaLabels.dropItems` | `DropItemsLabelContext` `{ count }` | `{count} items` | `Items ({ctx.count})` |
| `ariaLabels.dropDenied` | `DropDeniedLabelContext` `{ target }` | `Cannot drop here: {target} does …` | `Cannot drop here: {ctx.target} does …` |

The keys are new in this release (the earlier templates were rc07 work in progress); rc06 had no
placeholder labels.

```js
tree.translateCallback = ({ key, params }) => {
  const options = { ...params, count: params.ctx?.count };   // i18next plural forms
  return i18next.exists(key, options) ? i18next.t(key, options) : null;
};
```

### Stricter input values

The inputs run on core's converters, so a value the tree can't use is refused (a warning, the
`input-rejected` event, the previous value kept) instead of being accepted and misread.

| Input | rc06 | rc07 |
|---|---|---|
| `drag-drop-mode` | free text; an unknown value acted as `none` | `none \| self \| cross \| both`; anything else is refused |
| `tooltip-offset`, `context-menu-x-offset`, `context-menu-y-offset` | `"24px"` truncated to `24` | a bare integer; `"24px"`, `"8.5"`, `"1e3"` refused |
| `virtual-scroll-item-height` | truncated | a bare number |
| `drop-zone-max-width` / `dropZoneMaxWidth` | an integer; getter `120` | a CSS length (`8rem`, `30%`, `calc(…)`), a number = px; getter `'120px'` |
| `flat-indent-size` | free text; `"20"` produced an invalid `calc()` (no indent) | a CSS length, `"20"` → `20px`; default reads `var(--wtv-indent-size)` |
| `virtual-scroll-container-height` | free text | a CSS length, a number = px |
| `el.dragDropMode` / `flatIndentSize` / `virtualScrollContainerHeight` `= null` | accepted | refused — `el.x = undefined` or removing the attribute resets to the default |

`TreeViewConfig.dropZoneMaxWidth`, `flatIndentSize` and `virtualScrollContainerHeight` are typed
`string | number`.

### CSS classes and where elements live

| rc06 | rc07 |
|---|---|
| `.wtv__toggle-icon.expanded` | `.wtv__toggle-icon--expanded` |
| `.wtv-loader` (default loader) | `.wtv__loader` (`--wtv-loader-*` tokens and `wtv-loader-spin` unchanged) |
| `<style class="tv-custom-styles">` | `<style class="wtv-custom-styles">` (page layer: `wtv-custom-styles--page`) |
| `.wtv__drop-zones` (floating drop pads), `.wtv__touch-ghost` in the tree's shadow root | in a core layer: `div.km-layer` in `<body>` (or the open modal / popover the tree sits in) with its own shadow root; the rules moved from `tree.css` to `css/layers.css` |

The layer move is why an `overflow: hidden` or transformed ancestor no longer clips or shifts the
pads. The `--wtv-drop-zone-*` / `--wtv-touch-ghost-*` tokens, theme attributes and the tree's
`customStyles` / `getCustomStylesCallback` CSS are copied into the layer, so the look is the same.

### Renamed exports: menu divider, loader hook, labels

| rc06 | rc07 | Why |
|---|---|---|
| `menuDivider(text?)` | `createMenuDivider(text?)` | core's `create` = factory prefix; `{ divider: true, text? }` is unchanged |
| `window.components.renderLoaderCallback` | `window.components.renderLoadingCallback` | the same name as the instance `renderLoadingCallback` |
| `resolveLabel()` | removed | core `/locale` resolves labels; `DEFAULT_LABELS` / `TreeViewLabels` stay |
| `RendererConfig.labels`: the partial `labels` map | a core `Labels<TreeViewLabels>` object (`.text(key)`) | custom `TreeViewRenderer`s read texts through the same chain as the element |

### The engine and the headless state are renamed

For code that builds its own UI or imports the engine types. One settings shape for every Keenmate
engine: constructor → `setOptions(partial)` → `getOptions()`. No aliases.

| rc06 | rc07 |
|---|---|
| `WebTreeView` (class) | `TreeViewEngine` (UMD: `window.WebTreeView.TreeViewEngine`) |
| `webTreeView.update(partial)` | `engine.setOptions(partial)` — merges; absent keys keep their value |
| options typed `Partial<TreeViewConfig<T>>` | `TreeViewEngineOptions<T>` (constructor, `setOptions`, `getOptions`) |
| `webTreeView.getEngine()` | `engine.getState()` |
| `TreeEngine` | `TreeViewState` |
| `treeEngine.updateProps(partial)` | `state.setOptions(partial)` (+ `getOptions()`) |
| `TreeEngineConfig` / `TreeEngineSnapshot` / `TreeEngineEvents` | `TreeViewStateOptions` / `TreeViewStateSnapshot` / `TreeViewStateEvents` |
| `TreeEngine.findScrollableAncestor()` | removed (dead; scrolling uses core `findScrollContainer()`) |
| `renderStartCallback` / `renderProgressCallback` / `renderCompleteCallback` | `onRenderStart` / `onRenderProgress` / `onRenderComplete` |
| `containerResizeCallback` (renderer config) | `onContainerResize` |
| snapshot `contextMenuVisible` | `isContextMenuVisible` |
| `NodeCallbacks.onTouchDrag*`, engine `touchStart` / `touchMove` / `touchEnd` | removed (touch drag runs on core `createPointerDrag`) |
| `TreeViewRenderer.mount(container, controller: TreeEngine, config)` | `mount(container, state: TreeViewState, config)` — same object |

`<web-treeview>` users are not affected by this table. The element's own config type keeps its
name, `TreeViewConfig`.

### A touch drop reports a `PointerEvent`

The touch drag runs on core `createPointerDrag`, so a touch drop's `event` (`onNodeDrop`, the drop
callback contexts, `dropAt()`) is the `PointerEvent` that ended it — typed `DragEvent | PointerEvent`
(was `DragEvent | TouchEvent`). Mouse and pen keep HTML5 drag and drop.

### Keyboard-navigation methods are renamed

The 19 keyboard-navigation methods say what they do instead of the `nav` abbreviation: moving the
cursor is `focus`, Shift+key grows a range, so `extendSelection`. The rename covers the element,
`el.controller`, `TreeViewEngine`, the `TreeNavigation` interface and so the `navigationOverrides`
keys. Behaviour is unchanged; no aliases. Same in svelte-treeview 5.0.0-rc18.

| Key | rc06 | rc07 |
|---|---|---|
| (API) | `navTo(path)` | `focusAndSelectNode(path)` — focus, replace the selection, scroll into view (`focusNode` only moves the focus) |
| (API) | `navNext` / `navPrev` | `focusNext` / `focusPrevious` |
| ↓ / ↑ | `navNextSibling` / `navPrevSibling` | `focusNextAtLevel` / `focusPreviousAtLevel` — the next visible row at the same depth (can be a cousin in another branch) |
| → | `navInto` | `focusFirstChild` (expands first if collapsed) |
| ← | `navOut` | `focusParent` |
| Backspace | `navBackOut` | `collapseParent` (collapses the parent, then focuses it) |
| Enter | `navToggle` | `toggleFocusedNodeExpanded` |
| Home / End | `navFirst` / `navLast` | `focusFirst` / `focusLast` |
| PageDown / PageUp | `navPageDown` / `navPageUp` | `focusNextPage` / `focusPreviousPage` |
| Shift+↓ / ↑ | `navSelectNext` / `navSelectPrev` | `extendSelectionNext` / `extendSelectionPrevious` |
| Shift+Home / End | `navSelectFirst` / `navSelectLast` | `extendSelectionToFirst` / `extendSelectionToLast` |
| Shift+PageDown / PageUp | `navSelectPageDown` / `navSelectPageUp` | `extendSelectionNextPage` / `extendSelectionPreviousPage` |

### `copyNodeWithDescendants` is `duplicateNode`

One verb for "copy inside the tree, without the clipboard": `duplicateNode` (one subtree) next to
`duplicateNodes` (a batch); `copy*` stays the clipboard's (`copyNodes` / `cutNodes` / `pasteNodes`). Same
arguments and result, on the element, `TreeViewEngine`, `LTree` and now also `el.controller` (it was
missing there). No alias.

### `enable-flat-rendering` is removed

Flat rows are the only rendering mode, so `isFlatRenderingEnabled` / `enable-flat-rendering` had nothing
to switch — `false` only dropped the row indent and the progressive batching. Rows are always indented
by `flat-indent-size`; batching is `enable-progressive-render`'s alone. No alias.

## Behaviour changes

### Selection follows the core rules

The selected set, the Shift anchor and the click / Ctrl / Shift rules come from core
`createSelection`, the rules every Keenmate list, tree and grid shares. `selectedPaths`,
`selectionAnchor`, the methods and the `selection-change` detail are unchanged. Where rc06 differed:

| Case | rc06 | rc07 |
|---|---|---|
| Ctrl+Shift+click | replaced the selection with the range | adds the range |
| Click / arrow onto an unselectable node | cleared the selection | keeps it (focus still moves) |
| `selection-mode="single"`, Ctrl+click the selected node | kept it | clears it |
| `selectAll()` / Ctrl+A in single mode | selected every visible node | no-op |
| `selectNodes()` / `setSelectedPaths()` in single mode | all paths | the first selectable one |
| Shift+click with the anchor outside the range order | nothing | selects the clicked node |
| A click / key that changes nothing | fired `selection-change` | no event (methods still announce) |

### Collapse animates and returns a Promise

A collapse now plays its exit animation first and then applies. `collapseNodes()` / `collapseAll()`
(element and controller) return a Promise that settles after the collapse applied (rc06 returned
nothing), and `node-collapse` / `expanded-change` fire then. Code that reads `expandedPaths` or the
visible rows right after a collapse should `await` it. An expand that involves a collapsing node
(`collapseAll(); expandNodes(x)`) applies the pending collapse at once, so call order still holds.
`motion="none"` (element, section or `window.components.motion`) or OS reduced motion makes it
instant. See [Expand and collapse animate](#expand-and-collapse-animate).

### Row DOM ids come from the node path

A row's element id is `{treeId}-{node path}` (was `{treeId}-{node id}`; characters outside
`A-Z a-z 0-9 . -` are written `_<hex>_`). Node ids are the consumer's data and may repeat (a pasted
copy keeps its source id), so two rows could share an id and `aria-activedescendant` pointed at the
wrong one. Code that looked rows up by `#{treeId}-{id}` should use `[data-tree-path]`.

### Keyboard: exact modifiers, text fields and RTL arrows

- Built-in shortcuts (copy / cut / paste / delete, Ctrl+A, Shift+F10 / ContextMenu) are matched by
  core `matchesShortcut()`: modifiers match exactly, so Ctrl+Shift+C no longer copies and
  Ctrl+Delete no longer deletes.
- A key typed into a text field a `renderNodeCallback` drew inside a row is left to the field —
  Delete / Ctrl+C and the navigation keys (arrows, Home / End, Backspace, Enter / Space, Ctrl+A) no
  longer act on the tree.
- In a `dir="rtl"` tree ArrowLeft expands / moves into the first child and ArrowRight goes to the
  parent (WAI-ARIA tree). Read per key, so a runtime `dir` change applies at once. LTR is unchanged.

### Search folds more letters

The built-in index folds text with core `normalizeSearchText`, the folding web-multiselect, the
web-grid filter row and web-commandpalette use. Letters with no Unicode decomposition now fold too:
`lodz` finds `Łódź`, `strasse` finds `Straße`, `aerobic` finds `Ærobic`
(`ł ø đ ð ħ ı ß æ œ ŧ þ ĳ ŀ`). A custom `initializeIndexCallback` index keeps its own encoder.

### Search returns up to 1000 matches

`search-result-limit` (default `1000`) caps a search / filter; rc06 used FlexSearch's own silent
limit of 100. A large tree can show more matches than before; set `search-result-limit="100"` to
keep the old cap, and read `search-status-change` `detail.isLimited` to tell users a result was
truncated (see [New features — search](#new-features--search)). `indexer-batch-size` defaults to
`1000` (was `25`); each idle slot is time-boxed (≤ 16 ms) instead.

### Cascade checkboxes act on the visible matches while filtered

With `checkbox-mode="cascade"` and a filter active, a click on a parent's box checks / unchecks only
its visible descendants (all visible checked → uncheck them, otherwise check them). A branch with
hidden unchecked children then shows `[-]` and is not in `checkedPaths`; checks made while filtered
survive clearing the filter. `checkAll()` while filtered checks the visible nodes and keeps the hidden
checks. `checkNode(s)` / `uncheckNode(s)` and assigning `checkedPaths` stay whole-subtree.

### The context menu is a sheet on a phone

`menu-presentation` (default `auto`) opens the context menu as a bottom sheet on a phone; rc06
always showed the floating menu. Set `menu-presentation="floating"` to keep it, or `drawer` (with
`menu-side="start" | "end"`) for an edge drawer. Read when the menu opens, so `responsive` rules
apply.

### Popover and context-menu closing

- The full-label popover (`node-title-overflow="info"`) closes on any scroll that moves its row (the
  tree body, a wrapper, the page), when its row leaves the page, and on an outside click when the
  click **ends** (not at `pointerdown`). Escape closes one level at a time and is consumed by the
  popover, so it no longer also cancels a pending cut.
- The context menu closes only on a scroll that moves the tree — never a scroll inside the menu, an
  unrelated scroller or a bare mouse wheel.

### Render callbacks re-run only when their input changes

`renderNodeCallback` re-runs when the node's path / version or its render state (expanded, checked,
selected, focused, level, children, device class) changes, and in place when `labels`, `locale`,
`translateCallback`, the page-wide locale, `isReadonly` or the effective disabled state changes.
Any other input change re-runs none of the render callbacks, so a focused input inside a custom node
survives. A callback that returns a new element on each run gets it replaced by such a re-run.

### `el.controller` is frozen

`el.controller` (and `controller` on every ctx / event detail) is built by core
`createControllerFacade()`: the same members, but adding or replacing properties is ignored (throws
in strict mode). `selectionAnchor` stays settable.

### Core input rules

From core rc18–rc25: `el.x = undefined` resets an input to its default (rc06 warned); text inputs
accept `''`; enum attributes match case-insensitively; every refused write fires `input-rejected`
(`onInputRejected` twin); enum getters read their real default when unset (`clickBehavior`
`'expand-and-focus'`, `selectionMode` `'single'`, `dragDropMode` `'none'`, … — rc06 read `null`); a
default is never reflected. Log levels coalesce element → type → page.

## New features — accessibility and right-to-left

### ARIA tree semantics

The tree body is `role="tree"` (`aria-label` from `ariaLabels.tree`; `aria-multiselectable` in
multiple mode), every row is `role="treeitem"` with `aria-level`, `aria-posinset` / `aria-setsize`
(right inside a virtual window), `aria-expanded`, `aria-selected` and, with checkboxes,
`aria-checked` (`mixed` for a tri-state parent). Focus stays on the body; the focused row is
`aria-activedescendant` (core `/a11y`). Key bindings are unchanged.

### Screen-reader announcements

Through core `announce()`: a settled search ("12 results" / "1 result" / "No results found"), a drop
the tree placed ("Apricot moved into Banana", "3 items moved …", "… copied …") and a refused drop
with its reason. Each is an `ariaLabels.*` key; counts are locale-formatted; a label set to `''`
stays silent.

### Right-to-left

In a `dir="rtl"` tree the indent, gaps, drop pads, drop arrows and the drag-denied badge mirror
(logical CSS properties, `--_wtv-dir-sign`, `:dir(rtl)`), the drop position is measured from the
row's inline start, and the keyboard context menu opens at the node's start corner.

## New features — localization

### Page-wide labels and `translateCallback`

Labels resolve through core `createLabels`, per key: the instance `labels` → the tree's own
`translateCallback` → the page-wide `window.components.locale.translateCallback` → the page-wide
flat dictionary → English. Assigning `window.components.locale` re-renders the texts of every live
tree (expansion, selection, focus and scroll kept).

```js
window.components.locale = {
  labels: { 'web-treeview.messages.noData': 'Keine Daten' },
  translateCallback: ({ component, key, template, params, locale }) => i18n.t(key, params) ?? null,
};
tree.translateCallback = ({ key }) => myDict[key] ?? null; // this tree only, asked first
```

### `locale`

The `locale` attribute / property (BCP-47) formats the numbers in labels (`{ctx.count}` in
`ariaLabels.searchResults` / `ariaLabels.dropItems`, core `formatNumber`) and is the `locale` a
`translateCallback` receives. Unset (or `auto`) = `window.components.locale.locale` → the browser
language. A change re-applies the texts live.

### New label keys

`messages.loading` (lazy submenu row), `labels.dropBefore` / `labels.dropAfter` /
`labels.dropChild` (the floating drop pads, hard-coded English in rc06), `ariaLabels.tree`,
`ariaLabels.closeSheet` and `menuItems.back` (the phone sheet / drawer), and the announcements
`ariaLabels.searchResults` / `searchNoResults`, `movedInto` / `movedBefore` /
`movedAfter`, `copiedInto` / `copiedBefore` / `copiedAfter`, `dropItems`, `dropTreeRoot`,
`dropDenied`.

### `ctx.labels`, `isReadonly`, `isDisabled` in render callbacks

The ctx of `renderNodeCallback` and the region callbacks (`ContainerRenderContext`) carries
`labels` (`ctx.labels.text(key, params)` / `.html(key, params)`, the whole chain), `isReadonly` and
`isDisabled` (incl. a disabled `<fieldset>`).

## New features — icons

### Instance and page-wide icon hooks

`renderIconCallback(name, ctx)` (instance) is asked before
`window.components.renderIconCallback(name, ctx)`, so one tree needs no page setup. `ctx` =
`{ node, …render state, controller, element, component, prefix }`. Assigning the page-wide hook
after the tree rendered repaints the icons in place (expansion, selection, checks, focus and scroll
kept); a standalone engine calls `TreeViewEngine.refreshIcons()`. The repaint also re-runs
`renderNodeCallback` on the rendered rows, so a custom node drawing icons through core `renderIcon`
repaints too.

## New features — inputs, state and styling

### `disabled` / `readonly`

`disabled` / `isDisabled` (reflects): no user interaction (check, select, expand / collapse, drag,
drop, clipboard, context menu, keyboard), out of the tab order, `aria-disabled="true"`, dimmed by
`--wtv-disabled-tree-opacity`. `readonly` / `isReadonly` (reflects): no data change (no check, drag,
drop, cut / paste / delete; those menu items are greyed out) while the tree stays focusable and
navigable (keyboard, expand / collapse, selection, copy). Calls from code work under both; a disabled
or read-only tree never arms for `highlight-on-page-drag`.

### `expanded-paths` / `selected-paths` / `checked-paths` attributes

The three state sets are input rows now, so each is also an attribute: a JSON array
(`checked-paths='["1.2"]'`) or a comma-separated list. An invalid value is refused; removing the
attribute after the build empties the set; they take part in `setAttributes()` / `batch()`. Reading
right after an assignment, before the coalesced update, returns the assigned value.

### Custom CSS — page-wide and per instance

`window.components['web-treeview'].customStyles` (or `.getCustomStylesCallback(ctx)`) styles every
tree on the page; the tree's own `custom-styles` attribute / `customStyles` property (the
declarative twin of `getCustomStylesCallback`, which wins when both are set) comes after it. An
`@import` is linked once in the document head, so an imported icon font registers.

### Expand and collapse animate

Rows an expand reveals fade in while sliding down from `--wtv-row-animation-distance` (`0` = a plain
fade); rows a collapse hides shrink and fade. On by default — `motion` is the one switch (core
rule): `motion="none"`, a `data-motion` section, `window.components.motion` or OS reduced motion
make it instant; `--wtv-row-animation-duration: 0s` turns off just the rows.
`row-animation-limit` (default `50`, `0` = none) caps how many rows animate per expand. Never on
first render, a data reload, a filter or a virtual-scroll move.

### Context menu presentation and title

`menu-presentation` (`auto` | `floating` | `sheet` | `drawer`) and `menu-side` (`start` | `end`)
come from core `/menu`. The menu is named by its node: the node's display text is the menu's
`aria-label` and, on a phone, the sheet's header.

### Typed input properties

Every input is a typed property on `WebTreeViewElement` (`el.dragDropMode = 'both'`; a typo or a
wrong enum value is a compile error). New exported type `TreeViewElementConfig`.

## New features — search

### Result limit and search status

`search-result-limit` (default `1000`) and two events: `index-progress`
(`{ processed, total, isComplete }` — results are partial until `isComplete`) and
`search-status-change` (`{ searchTerm, matchCount, isLimited, limit, isIndexing }`), with `on*`
twins.

### Experimental filter scope

`filter-scope` (`matches` | `descendants` | `tree-depth` | `subtree-height` | `levels-below`),
`filter-descendant-depth` and `expand-filter-descendants` decide which descendants of a filter match
stay visible. Experimental: names and behaviour may change.

## New features — building your own UI

### `TreeViewEngine` and `TreeViewState`

The engine behind `<web-treeview>` is public as `TreeViewEngine` (`new TreeViewEngine(container,
options, renderer?)`, `setOptions()`, `getOptions()`, `getState()`, `refreshIcons()`), and the
headless tree state every renderer mounts on as `TreeViewState`. Both fill every option they aren't
given with the element's defaults (one source: the input table) — a bare
`new TreeViewState({ data })` reads `id` / `path` / `displayValue`, and an engine given only `nodes`
renders like the element (an rc06 `WebTreeView` without `displayValueMember` rendered every row as "[N/A]"). The engine
takes every per-element hook (`labels`, `locale`, `translateCallback`, `renderIconCallback`,
`renderLoadingCallback`, `menuPresentation`, …). `RendererConfig.renderContextVersion` tells a custom
renderer when to re-run the render callbacks. See "Build your own UI" in
[`docs/usage.md`](https://github.com/Keenmate/web-treeview/blob/prod/docs/usage.md#build-your-own-ui).

- Expanding / collapsing animates (see [Expand and collapse animate](#expand-and-collapse-animate)).

## Fixes

### Checkboxes and selection

- A cascade over three or more levels left a middle branch `[-]` after checking the root.
- `uncheckAll()` / assigning `checkedPaths` left an indeterminate `[-]` branch.
- Keyboard Enter / Space ignored accordion mode and `getIsCollapsibleCallback`; Backspace collapsed a
  non-collapsible parent.

### Drag, drop and clipboard

- A curated `beforeDragStartCallback` manifest (holes) was lost when a `beforeDropCallback` was set;
  a one-entry manifest ignored its holes; a hole under a top-level root couldn't be re-homed.
- A vetoed or refused mouse drop left the grabbed node selected.
- A same-tree drag-copy of a multi-selection copied locked nodes the move leaves out.
- `pasteNodes` dropped grandchildren when `nodeInputTransformationCallback` minted ids.
- A long press on a locked node auto-scrolled; `touchDragDelay` now applies live.
- A node path with a quote or a backslash threw from the touch-drag / drag-denied selectors.
- A tree with `highlight-on-page-drag` and no `drag-drop-mode` was armed by a page drag.

### Rendering, search and scrolling

- Every input change rebuilt all rows (and with a `renderNodeCallback`, redrew the header / footer),
  losing focus and transient row state.
- An edit while a filter was active didn't show until the filter changed; focus made while filtered
  pointed at the filtered copy.
- `virtual-scroll-container-height` in `rem` / `vh` rendered only a row or two.
- Safari: a search jump into a branch still rendering progressively stopped short.
- `scrollToPath()` near the end kept an unclamped `scrollTop`; `scroll-padding` on `.wtv__tree` is
  honoured.
- Node tooltips showed stale state; an open tooltip now updates in place.
- A click on a node checkbox didn't close the full-label popover.
- A lazy context submenu's loading row showed `…` instead of the label.

### Smaller

- `insertArray` counted a duplicate path as inserted (it is a failure now); `removeNode(path, false)`
  miscounted `statistics.nodeCount`; `statistics.filteredNodeCount` was always 0; the Delete command
  reported the wrong paths when a removal failed midway.
- Engine and search-index log lines follow the element's own `enableLogging()` /
  `disableLogging()`.
- An `@import` URL with a `"` in the custom CSS threw; its head `<link>` leaked on `destroy()`.
- `theme-source="closest"` follows a section themed after the tree connected.
