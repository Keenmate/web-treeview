Context Menu

Right-click menus: callback + custom-render approaches, submenus, offsets, theming

Positioning is handled by Floating UI

The menu and its submenus are placed by @floating-ui/dom (a runtime dependency). It uses computePosition with offset, flip, and shift middleware so the menu stays inside the viewport — submenus flip to the left edge when there's no room on the right, and autoUpdate keeps everything anchored on scroll/resize. The contextMenuXOffset/contextMenuYOffset props feed into the root menu's offset from the cursor.

CM01 · Callback Approach

Right-click any node. The web-treeview analog of svelte-treeview's getContextMenuItemsCallback is contextMenuCallback(node, close) => ContextMenuEntry[]. This demo shows shortcuts, a nested submenu, a named divider, className="danger", an isDisabled item, and an isVisible-gated item.

Activity Log:

Right-click a node to see the context menu
tree.contextMenuCallback = (node, close) => {
    const isFolder = node.data?.type === 'folder';
    const isReadonly = node.data?.readonly;
    const entries = [];

    if (isFolder) {
        entries.push({ icon: '📄', label: 'New File',  shortcut: 'N',       onclick: () => { log(`New file in "${node.data.name}"`); close(); } });
        entries.push({ icon: '📁', label: 'New Folder', shortcut: 'Shift+N', onclick: () => { log(`New folder in "${node.data.name}"`); close(); } });
        entries.push({ divider: true });
    }

    entries.push({ icon: '📋', label: 'Copy',  shortcut: 'C', onclick: () => { log(`Copied "${node.data.name}"`); close(); } });
    entries.push({ icon: '✂️', label: 'Cut',   shortcut: 'X', isDisabled: isReadonly, onclick: () => { log(`Cut "${node.data.name}"`); close(); } });
    entries.push({ icon: '📥', label: 'Paste', shortcut: 'V', isDisabled: !isFolder,  onclick: () => { log(`Paste into "${node.data.name}"`); close(); } });

    entries.push({ icon: '📤', label: 'Export As...', children: [
        { label: 'JSON', shortcut: 'J', onclick: () => { log('…as JSON'); close(); } },
        { label: 'XML',  shortcut: 'X', onclick: () => { log('…as XML');  close(); } },
        { label: 'CSV',  shortcut: 'C', onclick: () => { log('…as CSV');  close(); } },
    ]});

    entries.push({ divider: true, label: 'Danger zone' });
    entries.push({ icon: '✏️', label: 'Rename', shortcut: 'F2', isDisabled: isReadonly, onclick: () => { log('rename'); close(); } });
    entries.push({ icon: '🗑️', label: 'Delete', className: 'danger', isDisabled: isReadonly, onclick: () => { log('delete'); close(); } });
    entries.push({ icon: '🔒', label: 'Read-only file', isDisabled: true, isVisible: !!isReadonly });
    return entries;
};

CM02 · Custom Item Render

Where svelte-treeview offers a contextMenu snippet with ContextMenuItemC/ContextMenuDividerC components, web-treeview offers renderContextMenuItemCallback(item, node, container) — a fill-or-fall-through hook. Populate container to take over an item's inner markup; leave it empty and the component renders the default icon + label + shortcut. The outer <button> (classes, data-* attrs, disabled state, submenu hover) stays component-managed. Debug mode is on so the controls below preview live.

Action:

Right-click a person to see a rich context menu
// Customize specific items; leave the rest to default rendering.
//   container populated  → custom rendering
//   container left empty → default icon + label + shortcut
tree.renderContextMenuItemCallback = (item, node, container) => {
    const d = node.data;
    if (item.id === 'profile') {
        const initials = d.name.split(' ').map(w => w[0]).join('');
        container.innerHTML = `
            <span class="avatar">${initials}</span>
            <span class="info"><span>${d.name}</span><span class="role">${d.role}</span></span>`;
        return;
    }
    if (item.id === 'invoices') {
        container.innerHTML = `
            <span class="wtv__context-menu-icon">🧾</span>
            <span class="wtv__context-menu-label">Invoices</span>
            <span class="count-chip">${d.invoiceCount}</span>`;
        return;
    }
    // no innerHTML set → default rendering for this item
};

CM03 · Context Menu Callback API

Provide contextMenuCallback to build menu entries dynamically per node. It receives the LTreeNode and a close() function and returns a ContextMenuEntry[].

PropertyHTML AttrTypeDefaultDescription
contextMenuCallback — (node, close) => ContextMenuEntry[] undefined Builds the menu entries for a node. Return [] to show nothing.
shouldDisplayContextMenuInDebugMode — boolean false Show the menu at a fixed position (200px right, 100px down from the tree container) for dev/testing.

tree.contextMenuCallback = (node, close) => [
    { label: 'Copy', icon: '📋', shortcut: 'C',
      onclick: () => { copy(node); close(); } },
    { label: 'Edit', icon: '✏️',
      onclick: () => { edit(node); close(); } },
    { label: 'Export As...', icon: '📤', children: [
        { label: 'JSON', shortcut: 'J', onclick: () => { exportAs(node, 'json'); close(); } },
        { label: 'XML',  shortcut: 'X', onclick: () => { exportAs(node, 'xml');  close(); } },
    ]},
    { divider: true, label: 'Danger zone' },
    { label: 'Delete', className: 'danger', isDisabled: node.data.readonly,
      onclick: () => { del(node); close(); } },
];

CM04 · Per-Item Render API

renderContextMenuItemCallback runs once per item before default rendering. If it adds child nodes to container (the item's <button>), that markup is kept; otherwise the component falls back to the default icon + label + shortcut layout. Dividers are never passed to this callback.

PropertyTypeDescription
renderContextMenuItemCallback (item: ContextMenuItem, node: LTreeNode, container: HTMLElement) => void Custom render for one menu item. Fill container to override, leave empty to fall through to default.

Reusable inner classes

When you build custom markup, reuse .wtv__context-menu-icon, .wtv__context-menu-label, and .wtv__context-menu-shortcut so your items inherit the same alignment and theming as default items.

CM05 · ContextMenuEntry Types

The unified entry type: an entry is either a ContextMenuItem or a ContextMenuDivider.

PropertyTypeDescription
idstringOptional stable id (emitted as data-item-id; handy for renderContextMenuItemCallback branching).
labelstringDisplay text (required for items).
iconstringEmoji / text / CSS-class icon shown before the label.
shortcutstringKeyboard shortcut hint (right-aligned, muted).
isDisabledbooleanGreys the item out and blocks clicks.
isVisiblebooleanfalse skips rendering the item entirely.
classNamestringExtra CSS class (e.g. "danger" for red styling).
shouldCloseOnClickbooleanrc06 per-item opt-out. Defaults to true (activating an item dismisses the menu). Set false for incremental actions; your handler then dismisses via the close callback.
onclick() => void | Promise<void>Click handler. Parent items with children may omit it.
childrenContextMenuEntry[]Nested submenu entries (open on hover).

ContextMenuDivider

PropertyTypeDescription
dividertrueType discriminator for divider entries.
labelstringOptional named divider: ──── [label] ────.
 
interface ContextMenuDivider {
  divider: true;
  label?: string;            // named: ──── [label] ────
}

interface ContextMenuItem {
  id?: string;
  label: string;
  icon?: string;
  shortcut?: string;
  isDisabled?: boolean;
  isVisible?: boolean;       // false = skip rendering
  className?: string;        // e.g. "danger"
  shouldCloseOnClick?: boolean; // rc06 — default true
  onclick?: () => void | Promise<void>;
  children?: ContextMenuEntry[];
}

type ContextMenuEntry = ContextMenuItem | ContextMenuDivider;

CM06 · Menu Position Offset

Nudge the menu relative to the cursor with contextMenuXOffset (default 8) and contextMenuYOffset (default 0). Drag the sliders, then right-click a node to see where the menu lands.

tree.contextMenuCallback = getContextMenu;
tree.contextMenuXOffset = 8;   // px right of the cursor (default)
tree.contextMenuYOffset = 0;   // px below the cursor (default)

// or declaratively:
// <web-treeview context-menu-x-offset="8" context-menu-y-offset="0">

CM07 · CSS Customization

The context menu is styled through --wtv-context-menu-* custom properties (set on the host element or inline). Drag the controls — they re-style the menu, not the tree rows. Debug mode is on so changes preview live.
