DD01 · Drag Between Trees

Source tree (left): Drag to reorganize nodes (move). Enable "Allow Ctrl+drag to copy" then hold Ctrl while dragging to copy nodes. With selection-mode="multi" (default below), Ctrl/Shift+click multiple nodes and drag any one of them — the whole highlight set moves together. 🔒 File C (pinned) has isDraggable:false — it shows no grab cursor and won't start a drag (it's still a valid drop target). Target tree (right): Drag from source to add nodes. Starts empty to demo drop placeholder.

Clipboard (cross-tree): select nodes in either tree and press Ctrl/Cmd+C (copy) or X (cut), then click the other tree and Ctrl/Cmd+V to paste. While the target is empty, "Show drop zone when target empty" keeps the zone focusable so you can copy on the left, hover the zone, and paste without clicking first. Delete removes the selected node(s); Esc cancels a pending cut. These come from the built-in shouldHandleKeyboardShortcuts — this demo only supplies the paste transform (fresh ids / Copy N names) and a self-paste redirect.

DD02 · Multi-Drag (Select Multiple & Drag as Group)

            
Set selection-mode="multi" and the tree honors OS-explorer drag semantics: Ctrl/Shift-click several rows, then drag any one of them — the whole highlight set moves together. Grabbing a row that's not in the highlight set replaces the highlight with just that row, matching how Finder / Explorer behave.


            

                
Try it

                
    
                    
  1. Ctrl+click on three rows (e.g. Apple, Cherry, Eggplant) — you'll see them highlight.

  2. Drag any highlighted row and drop it onto another row.
    3. 
                    
  3. The whole set lands as a group: first node lands at the requested position, the rest chain after it as siblings.

  4. Shift+click selects a visual range between two rows.

DD03 · Restricted Drop Positions

            
Control which drop positions are valid per node using allowedDropPositionsMember (data-driven, shown below) or getAllowedDropPositionsCallback (runtime per-node logic). Both let the lib snap an attempted drop to the nearest allowed position. Try dragging items to different targets:


            

                
Node Types

                
    
                    
  • 🗑️ Trash - Only accepts child drops (drop INTO, not above/below)
    • 
                    
  • 📂 Projects - All positions allowed (default behavior)
    • 
                    
  • 📄 Files - Only before and after (can't drop INTO a file)
