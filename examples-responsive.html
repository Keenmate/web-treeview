The tree renders inline and never pops out, but every render callback's single ctx carries the NodeRenderContext fields — a live signal of the tree's own container box and the current device. Branch on it inside renderNodeCallback({ node, contentElement, container, deviceClass }) / renderIconCallback({ node, value, iconElement, container, deviceClass }) to adapt each row to the available space. The engine wires one shared ResizeObserver + device matcher from @keenmate/web-components-core/environment so you don't have to.

Re-render semantics

A device-class flip (mobile ↔ tablet ↔ desktop) is discrete, so it forces a full re-render — your callback runs again with the new ctx.deviceClass. A plain container resize updates ctx.container silently (virtual-scroll-first: no row churn on every pixel). If you want a width threshold to re-flow rows on the fly, drive it from your own observer (RS01 below) and nudge the tree — or key your layout off CSS that reads the live width.

RS01 · Container-Size Signal

renderNodeCallback reads ctx.container.width and ctx.deviceClass to decide what a row shows: wide rows carry the ISCO code + a device badge + the title; narrow rows drop the code so the long occupation titles still fit. tree.renderNodeCallback = ({ node, contentElement: el, container, deviceClass }) => {
  const narrow = container.width < 460;            // the tree's OWN box
  el.innerHTML = '';
  const row = document.createElement('span');
  row.className = 'isco-row';
  if (!narrow) {                                       // wide → code chip
    const code = document.createElement('span');
    code.className = 'isco-code';
    code.textContent = node.data.value;
    row.append(code);
  }
  const badge = document.createElement('span');        // ctx.deviceClass
  badge.className = 'dev-badge ' + deviceClass;
  badge.textContent = deviceClass;
  const label = document.createElement('span');
  label.className = 'isco-label';
  label.textContent = node.data.label;
  row.append(badge, label);
  el.append(row);
};

RS02 · Device-Adaptive Depth

The device-class flip is the re-render trigger: when the container crosses a device breakpoint, ctx.deviceClass changes and the tree re-renders. Here a page-side observer maps the live width to an expandLevel and reassigns it on the tree — a roomy box opens down to minor groups, a tight one shows only the ten major groups. Container-only resizes (no device flip) update ctx.container silently; this knob reacts to the derived breakpoints.

// ctx tells each row the device + box; your app picks the depth from the
// derived breakpoint and reassigns expandLevel (capability first, then width):
function resolveDepth(width, deviceClass) {
  if (deviceClass === 'mobile' || width < 380) return 1; // major groups
  if (width < 560)                              return 2; // + sub-major
  return 3;                                               // + minor
}
new ResizeObserver(([e]) => {
  const w = e.contentRect.width;
  tree.expandLevel = resolveDepth(w, deviceClassFromCtx);
}).observe(box);

RS03 · Label Overflow

The companion to the responsive signal: what a single node label does when it's wider than the row. renderNodeCallback wraps the title in a span whose overflow behaviour you pick — wrap (the label wraps, the row grows taller), or ellipsis (one clipped line with a native title tooltip on the full text). ISCO occupation titles are long, so in this deliberately narrow box the difference is obvious.

Ellipsis & uniform rows

ellipsis keeps every row one line tall — which is exactly what the virtual scroller wants (uniform row height lets it place thousands of rows cheaply). wrap produces variable-height rows; fine for small trees, but it defeats the fixed-height fast path. For large datasets, prefer ellipsis (+ a tooltip) over wrap.

Overflow:

In ellipsis mode, hover a clipped occupation title to see the full text.

let overflow = 'ellipsis';   // 'wrap' | 'ellipsis'

tree.renderNodeCallback = ({ node, contentElement: el }) => {
  el.innerHTML = '';
  el.className = 'ov-' + overflow;           // host decides wrap vs clip
  const label = document.createElement('span');
  label.className = 'ov-label';
  label.textContent = node.data.label;
  if (overflow === 'ellipsis') label.title = node.data.label; // full text on hover
  el.append(label);
};

RS04 · How the Signal Works

Everything above runs off the render state spread onto the single ctx your render callbacks receive. No bindings, no listeners, no teardown on your side — the renderer owns the observers and tears them down in destroy(). 

interface NodeRenderContext {
  deviceClass: 'mobile' | 'tablet' | 'desktop'; // classifyDevice(): capability + size
  container: { width: number; height: number }; // the tree's OWN border-box, in px
  isExpanded:    boolean;
  isChecked:     boolean;
  isSelected:    boolean;
  isFocused:     boolean;
  level:         number;   // 1-based depth
  hasChildren:   boolean;
}

// Both callbacks receive it on their one ctx (plus node / contentElement or value / iconElement):
tree.renderNodeCallback = ({ node, contentElement, deviceClass, container }) => { /* … */ };
tree.renderIconCallback = ({ node, value, iconElement, deviceClass, container }) => { /* … */ };

Where device & container come from

deviceClass and container are produced by @keenmate/web-components-core/environment (classifyDevice + observeEnvironment / observeElementSize), set up in the renderer's mount() and torn down in destroy(). Detection is feature-based (media queries), not UA sniffing, so it reacts to an orientation flip, a resize, or plugging in a mouse. A device-class change forces a full re-render; container size updates are applied silently. Requires core ≥ rc10. Parity with svelte-treeview's NodeRenderContext.
