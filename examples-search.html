Search & Filter

Filter the tree down to matches, or search-and-navigate while keeping the whole tree visible — powered by the internal FlexSearch index

SF01 · Search & Navigate

Type to query the tree. Filter mode hides non-matching nodes and auto-expands ancestors of matches. Search mode keeps the whole tree visible and jumps between matches. Use Enter for next, Shift+Enter for previous, Esc to clear. Toggle the mode with the icon button.

Filter

Note

The search index is built asynchronously after the data is set. If no results appear on the very first keystroke, wait a moment for indexing to finish.

// Enable the internal index + point it at the label member
tree.shouldUseInternalSearchIndex = true;
tree.searchValueMember = 'name';

function onInput() {
  const text = input.value.trim();
  if (mode === 'filter') tree.filterNodes(text);   // prune the tree
  results = tree.searchNodes(text);                 // query without pruning
  if (results.length) navigateTo(0);
}

function navigateTo(i) {
  tree.scrollToPath(results[i].path, {
    expand: true, highlight: true,
    scrollOptions: { behavior: 'smooth', block: 'center' },
    containerScroll: true
  });
}

SF02 · Filter vs Search

Both methods consult the same index, but they do different things to the tree. Run the two live demos below with the same query to feel the difference.

Method Effect on the tree Returns Use when
filterNodes(text) Prunes — hides non-matching nodes, auto-expands ancestors of matches void You want to narrow a large tree down to what matters
searchNodes(text) None — the tree stays fully intact LTreeNode<T>[] You want to count / navigate matches without losing context
scrollToPath(path, opts) Scrolls a node into view (auto-expands ancestors) Promise<boolean> Jumping to a search result ({ expand, highlight })

filterNodes — non-matches disappear

searchNodes — tree intact, matches listed

SF03 · Internal Search Index (FlexSearch)

Search is backed by an internal FlexSearch index, built asynchronously off the node data. Enable it with shouldUseInternalSearchIndex and tell it which value to index via searchValueMember (or the getSearchValueCallback for multi-field / computed text). Without the index enabled, filterNodes / searchNodes have nothing to query.

Property Attribute Type Description
shouldUseInternalSearchIndex should-use-internal-search-index boolean Enable the internal FlexSearch index (required for search/filter)
searchValueMember search-value-member string Property name whose value gets indexed (e.g. "name")
getSearchValueCallback — (set as JS property) (node) => string Custom extractor — index multiple fields / computed text
indexerBatchSize indexer-batch-size number Nodes indexed per async batch (tune for very large trees)
