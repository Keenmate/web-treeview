Every UI string goes through core /locale. Keys are flat <elementType>.<name> (messages.noData, labels.dropBefore, ariaLabels.tree, menuItems.copy, …) — the full list is the labels property in docs/usage.md. Per key: the instance labels (short or full web-treeview. key) → the element's own translateCallback → the page-wide translateCallback → the page dictionary window.components.locale.labels → the built-in English. The page-wide toggles (LO02, LO03, LO05) are page-wide: they change every tree on this page, on purpose. A shorter page-wide demo with the context menu and the drop pads is examples-basic.html BU08.

LO01 · Instance labels

Override texts on ONE element with the labels property (or a JSON labels attribute). A short key (labels.noDisplayValue — the text of a node without a name, the first row here) and a full key (web-treeview.ariaLabels.tree — the accessible name of the tree body) both work; every key you leave out stays English. The neighbour tree is untouched.

rendered strings

    
el.labels = {
  'labels.noDisplayValue': '(bez názvu)',            // short key
  'web-treeview.ariaLabels.tree': 'Soubory',         // full key
};
// or declaratively
<web-treeview labels='{"labels.noDisplayValue": "(bez názvu)"}'></web-treeview>









    
LO02 · Page-wide dictionary

    

        One flat dictionary on window.components.locale.labels — the app's translation JSON as loaded, full keys
        'web-treeview.<elementType>.<name>', other components' keys side by side — translates every tree on
        the page at once. Assigning window.components.locale re-renders the live trees (expansion and selection kept).
        Left: an empty tree (messages.noData); right: a search that matched nothing (messages.noResults).
        Right-click a node in LO01 for the translated menu items (menuItems.*). Keys an instance set itself (LO01) still win.

  },
};









    
LO03 · translateCallback

    

        An app with its own i18n (i18next, FormatJS, …) answers keys through a callback instead of a dictionary. It gets
        { component, key, template, params, locale } — key is the full
        web-treeview.<elementType>.<name> — and returns the text, or null = not mine. The element's
        own translateCallback is asked first (German, only messages.noData here); its null passes
        the key on to the page-wide one — the app's i18next (Slovak, with plural forms for the search announcement
        ariaLabels.searchResults: the bridge hands i18next params.ctx.count as its count — switch
        it on and press Search in LO05). The page itself runs without i18next: the same forms are picked with
        Intl.PluralRules('sk'). A key the instance labels set (the second tree's messages.noData)
        is never sent to any callback.
    

    

        
        
    

    

        

        

    

    
rendered strings

    
// the app's own i18next — its JSON, plural forms as i18next's _one / _few / _other suffixes
i18next.init({
  lng: 'sk',
  interpolation: { escapeValue: false },   // the tree writes labels as text, never as HTML
  resources: { sk: { translation: {
    'web-treeview': {
      messages: { noData: 'Žiadne údaje' },
      ariaLabels: {
        tree: 'Strom',
        searchResults_one: '{{count}} výsledok',
        searchResults_few: '{{count}} výsledky',
        searchResults_other: '{{count}} výsledkov',
      },
    },
  } } },
});

// page-wide — ONE generic bridge for every key of every component. params.ctx = the label's context;
// ctx.count = the number the text's noun agrees with → i18next's `count` (exists() needs it too)
window.components.locale = {
  translateCallback: ({ key, params }) => {
    const options = { ...params, count: params.ctx?.count };
    return i18next.exists(key, options) ? i18next.t(key, options) : null;   // null = not mine
  },
};

// one element — asked BEFORE the page-wide callback; null = not mine
el.translateCallback = ({ key }) => (key === 'web-treeview.messages.noData' ? 'Keine Daten' : null);









    
LO04 · Screen-reader name / tooltip follow

    

        An ariaLabels.x / tooltips.x nobody set takes the first customized key of the same
        <name>, so translating one string of a pair translates its twin. The tree's pair is loading:
        translate only the visible messages.loading (the loading row of a lazy context submenu) and the accessible
        name of the loading overlay, ariaLabels.loading — which nobody set — follows. The tree below is
        loading; the box reads the overlay's aria-label from the shadow root. (The tree has no
        tooltips.* keys.)

LO05 · locale + formatting

    

        Numbers in labels ({ctx.count} in the search announcement ariaLabels.searchResults, "Results: {ctx.count}")
        are formatted (core formatNumber) for the tree's locale input → the page language
        window.components.locale.locale → the browser. The tree formats no dates — this number is its only
        locale-specific output. The tree below has 1,234 nodes; Search filters them all and the screen-reader announcement
        (core announce(), the page's live region) is shown in the box. Set the element's locale and it
        wins over the page locale; unset it and the page locale applies again.

last screen-reader announcement

    
window.components.locale = { locale: 'de-DE' };
el.searchTerm = 'Item';   // announces "Results: 1.234"

// the element's own locale wins over the page one (removeAttribute / null = the page locale again)
el.setAttribute('locale', 'cs');   // announces "Results: 1 234"









    
LO06 · shouldEscapeLabels

    

        Does not apply: every tree label is plain text (written as textContent or an attribute), so a
        <b> in a label always shows as characters and window.components.security.shouldEscapeLabels
        has nothing to escape.
    









    
LO07 · Search announcement in Czech (plural rules)

    

        The tree's own translateCallback translates the screen-reader announcement of a settled search,
        ariaLabels.searchResults. params.ctx is its SearchResultsLabelContext
        { count, searchTerm } — ctx.count is the number of matches the noun agrees with, so
        Intl.PluralRules('cs') picks the form: "1 výsledek / 3 výsledky / 5 výsledků". Search a term that matches
        1, 3 or 5 nodes; the announcement goes to core's live region (announce()) and the box reads it from there.
        No i18n library needed; with i18next it is the generic bridge of LO03.
    

    

        
        
        
    

    

    
last screen-reader announcement

    
const plural = new Intl.PluralRules('cs');
const forms = { one: 'výsledek', few: 'výsledky', many: 'výsledku', other: 'výsledků' };

el.translateCallback = ({ key, params }) =>
  key === 'web-treeview.ariaLabels.searchResults'
    ? `${params.ctx.count} ${forms[plural.select(params.ctx.count)]} pro „${params.ctx.searchTerm}“`
    : null;   // null = not mine → the next layer / English

el.searchTerm = 'smlouva';   // announces "3 výsledky pro „smlouva“"

// with i18next: the one generic bridge of LO03 (ariaLabels.searchResults_one / _few / _other in the app's JSON)
