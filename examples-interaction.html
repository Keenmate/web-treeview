IN01 · Click Behavior & Multi-Select

click-behavior controls what happens when you click a node; selection-mode decides whether Ctrl/Shift+click can extend the set. The library tracks three independent node states:

  • focusedNode — single cursor row (clicks, arrow keys). Surfaces as focus-change; styled by focused-node-class.
  • selectedPaths — the multi-select set (Ctrl/Shift+click). Surfaces as selection-change; styled by selected-node-class.
  • checkedPaths — checkbox data state. Surfaces as checked-change.

With selection-mode="multiple": Click picks one node, Ctrl/Cmd+Click toggles individual nodes, Shift+Click range-selects, and Ctrl+A selects all (click the tree first for focus). range-selection-mode controls whether a Shift range includes collapsed children. Pick a Selected style below and build up a set to see it on every row.

How the styles stack — one channel per state

Each state owns a different visual channel so they compose instead of fighting: Selected (the set) paints the background as a soft tint; Focused (the single cursor row) is a thin inset outline ring, so it stacks cleanly on top of any background. After a plain click the same row is both (tint + ring); after a Shift+click range the intermediate rows are tinted only, while the last-clicked row is tinted and ringed. Each default is a fallback — pick a Selected or Focused style above and the built-in look steps aside.

Checkboxes are a separate channel — checkedPaths, independent of selection/focus. checkbox-mode=cascade makes a branch toggle its whole subtree (tristate on partial branches); independent toggles one node. With click-toggle-checkbox on, a plain row click flips that node's checkbox instead of just focusing the row.

Visual vs logical range — click components, then Shift+click README.md. In visual mode only currently-visible nodes between them are added; in logical mode the range walks the full tree in depth-first order, including children inside collapsed parents.

IN03 · Cascade Checkboxes & Value Policy

Two orthogonal knobs. checkbox-mode controls how checking a branch behaves; cascade-check-policy controls which paths the checked set emits (what checkedPaths / the checked-change event report). Flip them on one live tree and watch the emitted set change while the checkboxes stay put. (The click-toggle-checkbox knob — a plain row click flips the checkbox — lives in the IN01 picker above.)

What each option does

independent — each node toggles on its own; the policy is ignored and the emitted set is exactly the checked nodes.
cascade — checking a branch checks its whole subtree; a partial branch shows a tristate dash. Then the policy projects the emitted set:
  • rolled-up — a fully-checked subtree collapses to its root; a partial branch emits its individually-checked descendants.
  • leaves — only the checked leaf nodes.
  • all — every fully-checked node (branches + leaves).

IN04 · Silent State Restore

Restore tree state from URL parameters without firing selection callbacks. You share a link like ?nodePath=1.2.3; the page loads form data from the URL, and the tree just needs to scroll + visually select the matching node. Firing selection-change in that flow would re-trigger your form-loader and overwrite whatever the URL just supplied.

Pass { silent: true } to selectNode() / selectNodes() / clearSelection() / uncheckAll(). State (selected set, CSS class, focused node) still updates — only the selection-change / checked-change events are suppressed.

// Restore tree state from URL params without firing selection-change
function restoreFromUrl(nodePath) {
  loadFormDataFromUrl(nodePath);              // preserve this value
  tree.selectNode(nodePath, 'replace', { silent: true });
  tree.scrollToPath(nodePath, { expand: true, highlight: true });
}
