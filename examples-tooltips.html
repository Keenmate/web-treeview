TT01 · Plain-text tooltips

Set show-node-tooltips and a getNodeTooltipCallback that returns a string. The tooltip is portaled out of the tree, positioned with Floating UI, and shows on hover and keyboard focus. Rows whose callback returns an empty string get no tooltip.

Placement:

getNodeTooltipCallback({ node }) => string | HTMLElement | null. Return null / empty to skip a row. Tune timing with tooltip-delay (default { show: 400, hide: 100 }), tooltip-placement and tooltip-offset.

TT02 · Rich HTML tooltips

Return a built HTMLElement from the callback for rich content (the web-component analog of svelte-treeview's tooltip snippet). The callback gets the node, so the content can show its place in the tree: here a bold icon + name, the description in italics, and a chip — folder · N items for a branch, leaf otherwise — with the level and path. The callback runs each time the tooltip opens (and again while it's open), so it can show live state too: the second row of chips reads isSelected / isChecked / isExpanded. Click a row, tick a checkbox or press Space / Enter with a tooltip open — it follows. Tooltip content is display-only: no buttons or links.

TT03 · Theme reaction

The tooltip surface reads the shared --base-tooltip-* tokens (with a light/dark fallback), so it retints with the component theme. Flip the theme and hover a row — the tooltip follows, identical to how web-multiselect's option tooltip renders.

TT04 · Tooltip width

Three variables size the tooltip box. --wtv-tooltip-width is auto (shrink to the content) by default, capped by --wtv-tooltip-max-width (the wrap point, 32 × --wtv-rem = 320px); --wtv-tooltip-min-width sets a floor that still grows up to the max. For a fixed box set a width and clear the max (none). Change the values and hover a row — short and long descriptions show the difference.
