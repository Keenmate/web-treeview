Custom Layouts

Custom node templates, badges, empty/loading/header/footer slots, and a headless iOS-Files demo

CL01 · Custom Node Template

Use renderNodeCallback to render custom HTML for each tree node. The callback receives the LTreeNode and the content container (inside .wtv__node-content). This example shows file-type icons and sizes.

element.renderNodeCallback = (node, container) => {
    const name = node.data?.name || '';
    const size = node.data?.size || '';
    container.innerHTML = `
        <div class="custom-node">
            <span class="file-icon">${getIcon(name)}</span>
            <span class="name">${name}</span>
            ${size ? `<span class="file-size">${size}</span>` : ''}
        </div>`;
};

CL02 · Status Badges

The same renderNodeCallback hook can add dynamic badges that reflect per-node state (new, modified, deleted) — here a git-style status column.

CL03 · Header & Footer Slots

Add custom chrome above and below the scroll area with renderHeaderCallback and renderFooterCallback. Both receive a container element to populate.

tree.renderHeaderCallback = (container) => {
    container.innerHTML = `<div class="my-header">📁 File Browser</div>`;
};
tree.renderFooterCallback = (container) => {
    container.innerHTML = `<div class="my-footer">Right-click for context menu</div>`;
};

CL04 · Empty & Loading States

Customize what appears when the tree has no data (renderEmptyStateCallback) or is loading (renderLoadingCallback + the isLoading property).

tree.renderEmptyStateCallback = (container) => {
    container.innerHTML = `<div class="empty-state">🍃 No items</div>`;
};
tree.renderLoadingCallback = (container) => {
    container.innerHTML = `<div class="loading-state"><span class="spinner"></span> Loading…</div>`;
};

tree.isLoading = true;   // show the loading template
tree.isLoading = false;
tree.data = [];          // empty → empty template
tree.data = someRows;    // populated → the tree

CL05 · Toggle-Icon Modes & Icon Sets

The disclosure glyph is driven by icon-set (chevron | triangle | plus-minus | arrow) plus toggle-icon-mode (rotate = one glyph that rotates 90°, or swap = two glyphs). The deprecated expand-icon-class / collapse-icon-class / leaf-icon-class escape hatches still work for FontAwesome classes — inject FA into the shadow root via customStylesCallback.

CL06 · iOS Files Explorer (headless TreeController)

This whole UI renders without the <web-treeview> element. One headless TreeController owns the hierarchy; a custom renderer draws the iOS phone frame, nav, search, sort, breadcrumbs, file list, and detail sheet. The toggle below swaps the render path — Vanilla (imperative createElement) vs lit-html (declarative templates) — both drive the same controller + dataset + state.

9:41

Two renderers, one controller

The controller is created once; a mode flag chooses which render function the shared render() dispatch calls. Switching the toggle just re-renders — no controller rebuild, state (path, sort, search, open sheet) is preserved.

No web component used
TreeController is imported directly and used as a headless data engine. Everything visible is custom DOM.

Vanilla render path

  • document.createElement + appendChild
  • imperative addEventListener per row
  • full innerHTML = '' + rebuild each tick

lit-html render path

  • html` … ` tagged templates from esm.run
  • @click=${fn} event bindings
  • efficient DOM diffing on re-render

Controller APIs used

  • ctrl.getChildren(path) — folder contents
  • ctrl.flatNodesToRender — all nodes (deep search)
  • node.data — original user data
  • node.path — LTree path
  • node.hasChildren — folder check

CL07 · How it works

Two complementary patterns power this page: per-node render callbacks on the <web-treeview> element (CL01–CL05), and the headless TreeController for a 100%-custom UI (CL06).

Render callbacks (on the element)

CallbackSignatureRenders
renderNodeCallback(node, container) => voida node row's content
renderIconCallback(node, value, iconEl) => voidthe per-node icon (SVG/unicode/markup)
renderHeaderCallback(container) => voidchrome above the tree
renderFooterCallback(container) => voidchrome below the tree
renderEmptyStateCallback(container) => voidthe no-data state
renderLoadingCallback(container) => voidthe loading state (isLoading=true)
customStylesCallback() => stringCSS injected into the shadow root (supports @import)

Headless controller (no element)

import { TreeController } from '/src/index.ts';

const ctrl = new TreeController({
  data: myData,
  idMember: 'id',
  pathMember: 'path',
  treePathSeparator: '/',   // folder-style paths
  expandLevel: 99,
});

// Query the engine, render however you like:
ctrl.getChildren('Notepad++');   // direct children of a path
ctrl.flatNodesToRender;          // every node (for deep search)
ctrl.getNodeByPath(path);        // single node lookup
node.data; node.path; node.hasChildren;

Why headless?

When the target UI has nothing to do with a tree row — an iOS Files browser, an org chart, a badge cloud — skip the renderer entirely. Keep the controller for hierarchy, path math, search, and drag-drop; own every pixel yourself.
