What makes a row's left offset

A row sits in by toggle gutter + content padding + (level − 1) × indent. The indentation buttons only move --wtv-indent-size — multiplied by (level − 1), so at the root that's × 0 and the root rows never move. The fixed part left of every label is the toggle column (--wtv-toggle-icon-width, reserved on every row so leaf labels align under branch labels) plus the content's left --wtv-node-padding — independent of indent. Work and Reports have no icon: the icon column is reserved too (align-node-icons), so their labels still line up.

To tighten the root gap, lower --wtv-toggle-icon-width (and/or --wtv-node-padding); to change nesting density, use --wtv-indent-size. A toggle column of 0 hides the chevrons — a supported look for navigation-style trees: a row click and Enter still expand (with click-behavior="select" only a double-click or the keyboard does). All inherit through the Shadow DOM when set inline on <web-treeview>, so rows re-flow instantly.

BU03 · Accordion Expand

With expand-as-accordion="true", opening one branch automatically collapses its siblings at the same level. Useful when you want only one section open at a time (e.g. file managers, settings panels). User-driven toggles honor it; programmatic expandNodes() calls are unaffected.

Try expanding "Work", then "Personal" — with accordion on, opening "Personal" auto-collapses "Work". Untick the box and the two sections can stay open together.

BU04 · Custom Data Mappings

Map your own data shape to the tree using id-member, path-member, and display-value-member attributes.

// Your data can use any property names
const data = [
  { categoryId: 1, categoryPath: "1", label: "Electronics", ... },
  { categoryId: 2, categoryPath: "1.1", label: "Phones", ... }
];

// Map them to tree properties
element.setAttribute('id-member', 'categoryId');
element.setAttribute('path-member', 'categoryPath');
element.setAttribute('display-value-member', 'label');

BU07 · Programmatic Expand / Collapse

Use expandAll(), collapseAll(), expandNodes(path), and collapseNodes(path) to control the tree programmatically.

const tree = document.querySelector('web-treeview');

// Expand/collapse methods
tree.expandAll();
tree.collapseAll();
tree.expandNodes('1');      // Expand specific path
tree.collapseNodes('1');    // Collapse specific path

BU08 · Array Variants

All four methods accept either a single path or an array of paths. The array form runs once and emits a single change notification — useful when you need to open or close several places in the tree at the same time.

// Open multiple spines in one pass
tree.expandNodes(['1.1.1', '3.1.2']);

// Open entire subtrees
tree.expandAll(['1', '3']);

// Close several endpoints (spine ancestors stay open)
tree.collapseNodes(['1.1', '3.1']);

// Close entire subtrees
tree.collapseAll(['1', '3']);

BU09 · Exclusive Focus

Pass { isExclusive: true } to expandNodes or expandAll to open the target path and collapse everything currently open that isn't on its spine. Equivalent to collapseAll() + expandNodes(path) — but in a single pass with one emit, so listeners and CSS animations don't see the intermediate "all collapsed" state.

// "Focus" — open this path, close everything else. Single emit.
tree.expandNodes('1.1.1', { isExclusive: true });

// Multi-focus — union of spines stays open, rest collapses.
tree.expandNodes(['1.1.1', '3.1.2'], { isExclusive: true });

// "Focus on whole subtree" — opens the spine to the target AND its
// full subtree; collapses everything outside.
tree.expandAll('1', { isExclusive: true });

When to use isExclusive

Best for "spotlight" or "drill-in" UX where you want a single branch in focus. Without isExclusive, doing the same thing with collapseAll() followed by expandNodes(path) works, but emits twice — downstream listeners (transition animations, sync to a URL, virtualized renderers) see the intermediate fully-collapsed state. isExclusive: true walks only currently-expanded nodes (cheap) and emits once.

BU10 · Expand / Collapse API

interface ExpandOptions { isExclusive?: boolean; isSilent?: boolean }

expandNodes(paths: string | string[], options?: ExpandOptions)   // one level, ancestors opened
collapseNodes(paths: string | string[], options?: ExpandOptions): Promise<void>
toggleNodeExpanded(path: string, options?: ExpandOptions)

expandAll(paths?: string | string[] | null, options?: ExpandOptions)   // null = whole tree,
collapseAll(paths?: string | string[] | null, options?: ExpandOptions): Promise<void> // paths = those + descendants

// collapseNodes / collapseAll return Promise<void>: it settles after the hidden rows
// animated out and the collapse applied (BU11)

isSilent: true suppresses the events (node-expand, node-collapse, expanded-change) only — the tree always re-renders.

BU11 · Row Animation

Rows an expand reveals fade and slide in; rows a collapse hides shrink and fade out, then the node really collapses. It is on by default and part of motion: the motion attribute, a data-motion section, the page-wide window.components.motion or the OS reduced-motion setting turn it off together with every other animation. There is no on/off attribute — to turn off just the rows, set --wtv-row-animation-duration: 0s.

/* Rows only — everything else keeps animating */
web-treeview.my-tree { --wtv-row-animation-duration: 0s; }

/* Slower rows, plain fade (no slide) */
web-treeview.my-tree {
  --wtv-row-animation-duration: var(--wtv-transition-slow);
  --wtv-row-animation-distance: 0;
}
<!-- motion="none" (or window.components.motion = 'none') = no animation at all -->
<web-treeview motion="none"></web-treeview>

<!-- At most 5 rows animate per expand / collapse; the rest appear / go at once -->
<web-treeview max-animated-row-count="5"></web-treeview>
// The collapse applies after the rows animated out — await it before reading state
await tree.collapseAll();
await tree.collapseNodes('1');

Only expands and collapses animate — never the first render, a reload, a filter or a re-render. Toggling a node again while its rows are animating out cancels the collapse (it stays open). max-animated-row-count is a performance cap: expanding a node with thousands of children animates just the first rows.

BU13 · Page-wide labels — window.components.locale

Every UI string goes through core /locale: the instance labels win, then the page-wide flat dictionary window.components.locale.labels['web-treeview.<key>'], then English. Assigning the page object re-renders every live tree — texts only, expansion and selection are kept. Right-click a node for the built-in menu items, drag a node over another for the floating drop pads (labels.dropBefore / labels.dropAfter / labels.dropChild); the empty tree in the middle keeps its own messages.noData.

window.components.locale = {
  labels: {
    'web-treeview.messages.noData': 'Žádná data',
    'web-treeview.menuItems.copy': 'Kopírovat', 'web-treeview.menuItems.cut': 'Vyjmout',
    'web-treeview.menuItems.paste': 'Vložit', 'web-treeview.menuItems.delete': 'Smazat',
    'web-treeview.labels.dropBefore': 'Před', 'web-treeview.labels.dropAfter': 'Za', 'web-treeview.labels.dropChild': 'Dovnitř',
  },
  // optional: i18next / ICU for every label (key = the full key, 'web-treeview.menuItems.copy')
  // translateCallback: ({ key, params }) => i18next.t(key, { ...params, count: params.ctx?.count }),
};
window.components.locale = null;   // back to English
