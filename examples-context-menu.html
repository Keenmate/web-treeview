Context Menu

Right-click menus: callback + custom-render approaches, submenus, offsets, theming

Positioning is handled by Floating UI

The menu and its submenus are web-components-core's shared openMenu(), placed by core's /positioning anchor() (over @floating-ui/dom, which core brings in): offset, flip and shift keep the menu inside the viewport — submenus flip to the left edge when there's no room on the right, and autoUpdate keeps everything anchored on scroll/resize. The contextMenuXOffset/contextMenuYOffset props feed into the root menu's offset from the cursor.

CM01 · Callback Approach

Right-click any node. web-treeview builds the menu with getContextMenuItemsCallback(ctx) => TreeMenuEntry[] — ctx is { node, path, parent, siblings, controller, element } and the entries are core action items. This demo shows shortcuts, a nested submenu, a named divider (menuDivider(text)), an isDanger item, an isDisabled item, and an isVisible-gated item. An enabled leaf closes the menu after its onClick — no close() needed.

Activity Log:

Right-click a node to see the context menu
import { menuDivider } from '@keenmate/web-treeview';

tree.getContextMenuItemsCallback = ({ node }) => {
    const isFolder = node.data?.type === 'folder';
    const isReadonly = !!node.data?.readonly;
    const entries = [];

    if (isFolder) {
        entries.push({ id: 'new-file',   icon: '📄', text: 'New File',   shortcut: 'N',       onClick: () => log(`New file in "${node.data.name}"`) });
        entries.push({ id: 'new-folder', icon: '📁', text: 'New Folder', shortcut: 'Shift+N', onClick: () => log(`New folder in "${node.data.name}"`) });
        entries.push(menuDivider());
    }

    entries.push({ id: 'copy',  icon: '📋', text: 'Copy',  shortcut: 'C', onClick: () => log(`Copied "${node.data.name}"`) });
    entries.push({ id: 'cut',   icon: '✂️', text: 'Cut',   shortcut: 'X', isDisabled: isReadonly, onClick: () => log(`Cut "${node.data.name}"`) });
    entries.push({ id: 'paste', icon: '📥', text: 'Paste', shortcut: 'V', isDisabled: !isFolder,  onClick: () => log(`Paste into "${node.data.name}"`) });

    entries.push({ id: 'export', icon: '📤', text: 'Export As...', children: [
        { id: 'json', text: 'JSON', shortcut: 'J', onClick: () => log('…as JSON') },
        { id: 'xml',  text: 'XML',  shortcut: 'X', onClick: () => log('…as XML') },
        { id: 'csv',  text: 'CSV',  shortcut: 'C', onClick: () => log('…as CSV') },
    ]});

    entries.push(menuDivider('Danger zone'));
    entries.push({ id: 'rename', icon: '✏️', text: 'Rename', shortcut: 'F2', isDisabled: isReadonly, onClick: () => log('rename') });
    entries.push({ id: 'delete', icon: '🗑️', text: 'Delete', isDanger: true, isDisabled: isReadonly, onClick: () => log('delete') });
    entries.push({ id: 'readonly', icon: '🔒', text: 'Read-only file', isDisabled: true, isVisible: isReadonly });
    return entries;
};

CM02 · Custom Item Render

Where svelte-treeview offers a contextMenu snippet with ContextMenuItemC/ContextMenuDividerC components, web-treeview offers renderContextMenuItemCallback({ node, menuItem, buttonElement, … }) — a fill-or-fall-through hook. Populate buttonElement to take over an item's inner markup; leave it empty and the component renders the default icon + label + shortcut. The outer item element (classes, ARIA, data-* attrs, disabled state, submenu hover, keyboard) stays component-managed. Right-click a node to preview the controls below.

Action:

Right-click a person to see a rich context menu
// Customize specific items; leave the rest to default rendering.
//   buttonElement populated  → custom rendering
//   buttonElement left empty → default icon + label + shortcut
tree.renderContextMenuItemCallback = ({ node, menuItem, buttonElement }) => {
    const d = node.data;
    if (menuItem.id === 'profile') {
        const initials = d.name.split(' ').map(w => w[0]).join('');
        buttonElement.innerHTML = `
            <span class="avatar">${initials}</span>
            <span class="info"><span>${d.name}</span><span class="role">${d.role}</span></span>`;
        return;
    }
    if (menuItem.id === 'invoices') {
        buttonElement.innerHTML = `
            <span class="km-menu__icon">🧾</span>
            <span class="km-menu__label">Invoices</span>
            <span class="count-chip">${d.invoiceCount}</span>`;
        return;
    }
    // no innerHTML set → default rendering for this item
};

// The items carry no onClick — every activation fires the `action` event.
tree.addEventListener('action', ({ detail }) => log(detail.id, detail.node));

CM03 · Context Menu Callback API

Provide getContextMenuItemsCallback to build menu entries dynamically per node. It receives one ctx — { node, path, parent, siblings, controller, element } — and returns a TreeMenuEntry[]: core action items, dividers, or built-in action names. Every activation fires the action event (twin onAction(detail)); beforeActionCallback(detail) returning false cancels it.

PropertyHTML AttrTypeDefaultDescription
getContextMenuItemsCallback — (ctx: TreeMenuContext) => TreeMenuEntry[] undefined Builds the menu entries for a node. Return [] to show nothing.
beforeActionCallback — (detail) => void | false | Promise<void | false> undefined Runs before an item activates; false cancels its onClick, the action event and the built-in.
onAction / action event — (detail: TreeViewActionEventDetail) => void undefined An item was activated. detail: action (built-in name or 'custom'), id, item, source: 'context-menu', node / path / parent / siblings. Fires after the item's onClick, before the built-in. 
import { menuDivider, type TreeMenuEntry } from '@keenmate/web-treeview';

tree.getContextMenuItemsCallback = ({ node }): TreeMenuEntry[] => [
    'copy', 'cut', 'paste',               // built-ins: act on the node (or the selection it's in)
    { id: 'edit', text: 'Edit', icon: '✏️',
      onClick: ({ node }) => edit(node) },
    { id: 'export', text: 'Export As...', icon: '📤', children: [
        { id: 'json', text: 'JSON', shortcut: 'J', onClick: () => exportAs(node, 'json') },
        { id: 'xml',  text: 'XML',  shortcut: 'X', onClick: () => exportAs(node, 'xml') },
    ]},
    { id: 'recent', text: 'Recent', getChildrenCallback: async () => loadRecent(node) },  // lazy submenu
    menuDivider('Danger zone'),
    { id: 'delete', text: 'Delete', isDanger: true, isDisabled: node.data.readonly,
      onClick: () => del(node) },
];

// One handler for every item (fires after onClick, before a built-in):
tree.onAction = ({ action, id, node }) => console.log(action, id, node.path);
// Veto an activation:
tree.beforeActionCallback = ({ id, node }) => {
    if (id === 'delete' && node.data.locked) return false;
};

CM04 · Per-Item Render API

renderContextMenuItemCallback runs once per item before default rendering. If it adds child nodes to ctx.buttonElement (the item element, role="menuitem"), that markup is kept; otherwise the component falls back to the default icon + label + shortcut layout. Dividers are never passed to this callback. To take over the whole menu instead, use renderContextMenuCallback({ node, path, parent, siblings, containerElement, controller }) and close it via ctx.controller.closeContextMenu().

PropertyTypeDescription
renderContextMenuItemCallback (ctx: { node, path, parent, siblings, menuItem: TreeMenuItem, buttonElement: HTMLElement }) => void Custom render for one menu item. Fill buttonElement to override, leave empty to fall through to default.
renderContextMenuCallback (ctx: { node, path, parent, siblings, containerElement: HTMLElement }) => void Take over the whole menu: fill containerElement; close via ctx.controller.closeContextMenu().

Reusable inner classes

When you build custom markup, reuse .km-menu__icon, .km-menu__label, and .km-menu__shortcut so your items inherit the same alignment and theming as default items.

CM05 · TreeMenuEntry Types

An entry is a TreeMenuItem (a core action item), a MenuDivider, or a built-in action name: 'copy' | 'cut' | 'paste' | 'delete' | 'expand' | 'collapse'. Built-ins act on the node — or on the whole selection when the node is in it — and come with default text / disabled / danger state.

PropertyTypeDescription
idstringIdentifies a custom item; reported in the action event and rendered as data-id (the button also carries data-action: the built-in name or custom). Handy for renderContextMenuItemCallback branching.
actionTreeViewAction | 'custom'Built-in action to run (same as passing the plain string). Omit for a custom item.
textstringDisplay text (plain text).
iconstringEmoji / text / CSS-class icon shown before the text.
shortcutstringKeyboard shortcut hint (right-aligned, muted; pressed while the menu is open, it activates the item).
tooltipstringNative tooltip (title) on the item.
isDisabledbooleanGreys the item out and blocks clicks.
isVisiblebooleanfalse skips rendering the item entirely.
isDangerbooleanDestructive (red) styling — .km-menu__item--danger.
isToggledbooleanToggle state is on. Defining it (or getIsToggledCallback) makes the item a menuitemcheckbox with aria-checked; .km-menu__item--toggled when on. Still clickable.
cssClassstringExtra CSS class(es) on the item button.
get*Callback(ctx)(ctx: TreeMenuContext) => …Dynamic variants that win over the static value: getTextCallback, getIconCallback, getTooltipCallback, getClassCallback, getIsVisibleCallback, getIsDisabledCallback, getIsToggledCallback.
shouldCloseOnClickbooleanDefaults to true (activating a leaf dismisses the menu). Set false for incremental actions; close later via detail.controller.closeContextMenu().
onClick(detail) => void | Promise<void>Click handler; receives the action event detail (the menu ctx + action, id, item, source). Optional — every enabled leaf activates and fires action.
childrenTreeMenuEntry[]Nested submenu entries (open on hover).
getChildrenCallback(ctx) => TreeMenuEntry[] | Promise<…>Lazy / dynamic submenu (wins over children); a loading row shows while it resolves.

PropertyTypeDescription
dividertrueType discriminator for divider entries.
textstringOptional named divider: ──── [text] ────. Or build one with menuDivider(text?) (exported).
 
interface MenuDivider {
  divider: true;
  text?: string;             // named: ──── [text] ────   (menuDivider(text))
}

interface TreeMenuItem {
  action?: TreeViewAction | 'custom';
  id?: string;
  text?: string;
  icon?: string;
  shortcut?: string;
  tooltip?: string;
  cssClass?: string;
  isVisible?: boolean;       // false = skip rendering
  isDisabled?: boolean;
  isDanger?: boolean;
  isToggled?: boolean;       // menuitemcheckbox + aria-checked
  getTextCallback?(ctx: TreeMenuContext): string;   // + getIcon/Tooltip/Class/IsVisible/IsDisabled/IsToggledCallback
  shouldCloseOnClick?: boolean; // default true
  onClick?(detail: TreeViewActionEventDetail): void | Promise<void>;
  children?: TreeMenuEntry[];
  getChildrenCallback?(ctx: TreeMenuContext): TreeMenuEntry[] | Promise<TreeMenuEntry[]>;
}

type TreeViewAction = 'copy' | 'cut' | 'paste' | 'delete' | 'expand' | 'collapse';
type TreeMenuEntry  = TreeMenuItem | MenuDivider | TreeViewAction;

CM06 · Menu Position Offset

Nudge the menu relative to the cursor with contextMenuXOffset (default 8) and contextMenuYOffset (default 0). Drag the sliders, then right-click a node to see where the menu lands.

tree.getContextMenuItemsCallback = getMenuItems;
tree.contextMenuXOffset = 8;   // px right of the cursor (default)
tree.contextMenuYOffset = 0;   // px below the cursor (default)

// or declaratively:
// <web-treeview context-menu-x-offset="8" context-menu-y-offset="0">

CM07 · CSS Customization

The context menu is styled through --wtv-context-menu-* custom properties (set on the host element or inline). Drag the controls — they re-style the menu, not the tree rows. Right-click a node to preview the changes.
