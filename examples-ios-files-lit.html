iOS Files Explorer (lit-html)

Headless TreeController + lit-html templates — declarative rendering, no framework

9:41

lit-html Version

Same iOS Files Explorer, but rendered with lit-html tagged template literals instead of imperative DOM manipulation.

lit-html from CDN
No build step required. Imported directly via esm.run CDN.

Import

import { html, render } from
  'https://esm.run/lit-html@3';
import { TreeController } from
  './dist/web-treeview.js';

Declarative File Row

const fileRow = (node) => html`
  <button class="ios-file-row"
    @click=${() => onRowClick(node)}>

    <span class="ios-file-icon">
      ${getFileIcon(node)}
    </span>

    <div class="ios-file-info">
      <span class="ios-file-name">
        ${node.data?.name}
      </span>
      <span class="ios-file-meta">
        ${getMeta(node)}
      </span>
    </div>

    ${node.data?.isDirectory ? html`
      <span class="ios-file-chevron">
        &rsaquo;
      </span>
    ` : ''}
  </button>`;

Rendering

function update() {
  const children = sortNodes(
    ctrl.getChildren(currentPath)
  );

  render(html`
    ${children.map(fileRow)}
  `, fileList);

  render(breadcrumbsTemplate(),
    breadcrumbsEl);
}

Key Differences from Vanilla

  • No createElement / appendChild
  • No innerHTML string building
  • Efficient DOM diffing on re-render
  • Event handlers via @click=${fn}
  • Conditional rendering with ternary
  • Lists with .map()

APIs Used

  • ctrl.getChildren(path) — folder contents
  • node.data — original user data
  • node.path — LTree path
